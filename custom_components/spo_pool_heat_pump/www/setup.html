SPO Pool Heat Pump

This integration speaks Modbus RTU on RS-485 — the same bus as the heat-pump display. Three jobs: wire a parallel tap, put the DR164 on your LAN, then set it as a transparent TCP Server so Home Assistant can listen. Serial USB and Modbus-TCP gateways are not used. Do not add Home Assistant’s separate Modbus integration.

1. Wire it up

The factory WiFi / DTU already sits on four pins: +, A, B, and G. Tap the same four on the DR164 in parallel — do not cut the panel cable or replace the display.

  • DR164 + / DC+ → heat-pump bus + (same 12 V rail as the WiFi module).
  • DR164 A / RX → heat-pump bus A.
  • DR164 B / TX → heat-pump bus B.
  • DR164 G / GND → heat-pump bus G. If the module has a separate DC− screw, join it to G.
  • If Home Assistant later reports no frames or every CRC fails, swap A and B.

Wiring diagram: README.md (docs/images/dr164-parallel-tap.png in the repo).

Parallel tap only. Leave a factory WiFi / DTU module plugged in if you still want writes to go to slave 99. Unplugging a live DTU while the write path is still “DTU slave 99” will drop commands on the floor.

2. Add it to the network

  1. Power the DR164. On your phone, join the open AP USR-DR164-xxxx.
  2. Open http://10.10.100.254 and sign in as admin / admin.
  3. Change that password before the device sits on the home LAN.
  4. Set STA / station Wi-Fi to your home SSID and password. Apply and wait for it to reboot onto the LAN.
  5. In the router, find the new DHCP lease and reserve that IP (or set a static address in the same subnet as Home Assistant).
  6. Leave the phone AP. Open the reserved LAN IP in a browser to finish setup.

Home Assistant and the DR164 must be on the same LAN. One TCP client only — do not point a second app at port 8899 at the same time.

3. Set the DR164 work mode

On the DR164 web UI (now at the reserved LAN IP):

  • Socket A = TCP Server, transparent (pass-through). Port 8899.
  • Not Modbus gateway, MQTT, HTTP client, PUSR cloud, heartbeat, registration, or Event.
  • Serial / UART: 9600 8N1.
  • UART time / idle trigger = 20 ms (AT+UARTTM). Leave the length trigger at 1400.

The heat pump speaks Modbus RTU on the wire. The DR164 only copies those bytes onto TCP. Home Assistant is the Modbus client.

4. Add it in Home Assistant

  1. Settings → Devices & services → Add integration → SPO Pool Heat Pump.
  2. Host = the reserved DR164 IP. Port = 8899.
  3. Detection listens about 5 seconds, then pre-selects a profile and says why. Keep it unless the name on the case is a different family. Compatible badges are listed on each option (Oasis / Warmpool → Hayward; Azuro / Mountfield → MIDA Cosma; SuperMini → PHNIX Mini; slave 50 → Fairland CN13; IPS Pro / InverX → coil map). Not listed? Unknown heat pump — dump only, then Settings → Bus dump. AquaTemp on the phone does not prove the wire map.
  4. Write path: DTU slave 99 when the factory WiFi module is on the bus. If detection saw no slave 99, keep slave 2. Mini lists both; pick slave 2 when there is no WiFi module.
  5. Fairland CN13 / IPS Pro: confirm Modbus slave (H37) (CN13 default 50, IPS Pro usually 1).
  6. Leave Allow changing service settings off unless you intend to change H/F/D special-menu values. Those can damage the unit.

Cannot connect? Confirm Socket A is TCP Server on 8899, the IP is reserved, the pump is powered, and try swapping A/B. Serial USB adapters are not a v1 transport.

Why this is not the Home Assistant Modbus integration

The heat pump is Modbus — Modbus RTU on RS-485. This integration speaks that protocol itself. Do not add Settings → Devices & services → Modbus, and do not switch the DR164 to Modbus gateway.

  • The display already masters the bus. It broadcasts holding registers (FC16 starting at 2001). Home Assistant mostly listens; it is not a simple “poll slave X every 10 s” client.
  • Writes go to the factory DTU (slave 99) or, with no WiFi module, HA answers like a second panel (slave 2). Core Modbus cannot impersonate a slave or share the wire with the panel and the DTU.
  • The DR164 must stay a transparent TCP Server: raw RTU bytes in, raw RTU bytes out. “Modbus gateway” wraps those bytes in Modbus-TCP and only forwards poll/reply. Broadcasts and slave-2 answers never arrive intact.

Fairland-style units that are polled still go through this integration so the climate entity, card, and write rules stay the same. Serial USB and Modbus-TCP gateways are not a v1 transport.
